# 璃游 LumaDock 0.2 使用说明

璃游是 Mac 专用游戏启动器，适用于 Apple Silicon、macOS 26 及以上。应用使用本地 ad-hoc 签名，尚未公证。

全部依赖、安装方式与实际验证项目见[环境要求与修复方法](环境要求.md)。Python 已随完整应用提供，不需要玩家另外安装系统 Python。

1. 打开 DMG，将 **LumaDock.app** 拖入“应用程序”。首次打开若被 macOS 拦截，在“系统设置 → 隐私与安全性”中核对来源后选择“仍要打开”。
2. 先完成向导第一步“检查并安装环境”。应用自动检查硬件、系统、完整 Xcode、Metal、应用组件与可用空间。缺少 Xcode 时先获取完整应用，打开一次，完成许可及初始组件安装；可填写实际 Developer 目录再重新检查。缺少 Metal 时点击安装按钮，方式见 [Apple 说明](https://developer.apple.com/documentation/xcode/downloading-and-installing-additional-xcode-components)。其他构建依赖已随应用提供。检查通过后才能继续。
在环境检查页先点击“选择 nxnative 目录…”，选择自行获取并解压、包含 `dm` 与 `scripts` 的完整源码根目录；璃游不附带引擎，也没有下载按钮。随后点击“准备引擎工具”。首次需要 [.NET 10 SDK（macOS Arm64）](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)，并可能从 NuGet 恢复依赖。所有编译和适配仅发生在私有副本，原目录保持不变；完成后重新检查。

3. 在第二步选择游戏库文件夹。可以选择外置硬盘；运行和准备游戏时保持连接。
4. 在第三步导入玩家自己的 `prod.keys` 文本文件。通常只需导入一次，可供多款游戏共用。格式通过后才能继续，首次读取 NSP 时进一步验证解密能力。密钥不上传，权限为 0600。
5. 在第四步点击“添加游戏”，多选本体、更新和 DLC 的 NSP、XCI、NSZ、XCZ，或扫描含混合格式的文件夹。NSP、XCI 由 nxnative 直接读取并入库；NSZ、XCZ 使用游戏库密钥在私有临时目录解压为 NSP、XCI，再继续入库和自动准备，无需进入“文件转换”页面。支持中文和空格路径。之后也可以从工具栏、菜单或拖入添加；环境或密钥未就绪时，均会引导到对应步骤。首次导入会完整读取并校验文件，可能需要一些时间。
6. 默认开启“导入后自动准备支持的游戏”。导入成功且文件齐全、版本与构建标识匹配时，再次检查工具链并加入准备队列；重复导入不会触发准备。缺少内容会列在游戏详情中，补齐后再准备。若工具链后来不可用，保留导入结果，完成安装后手动点击“准备运行文件”。“准备任务”显示真实阶段、计数或不定进度。成功后由你点击“启动游戏”，不会自动启动。可在向导或设置关闭自动准备，改为手动准备。

首次运行向导的每一步都可以暂时离开，包括环境检查进行中或组件缺失时。点击“稍后设置”或按 Esc 返回游戏库，点击“退出璃游”或按 ⌘Q 正常退出。之后可点击游戏库的“继续设置”，或从设置重新打开向导。暂时关闭不会将设置标记为完成；下次启动仍显示未完成的向导，导入和准备游戏也仍需通过必要检查。

应用没有内置任何游戏、更新、DLC、固件、玩家密钥、游戏封面或玩家缓存。封面仅从玩家导入的游戏读取。只有引擎白名单中已适配的指定版本允许构建；其他游戏可以登记但无法构建。兼容性等级以实际 Mac 测试为依据。

游戏准备与 IPA 导出使用分段里程碑进度，显示当前步骤及作用、已用时间、预计剩余时间和预计完成时刻；悬停各段可查看说明。首次为参考估时，成功且未命中缓存的阶段会积累本机历史，按游戏、目标平台和工具链隔离；缓存命中、失败或取消不训练估时。浅色填充是时间估计，数字百分比仍只来自实际计数。估时仅供参考，不是完成时限。

## 文件转换

从侧栏打开“文件转换”，选择格式转换、压缩、解压或合并，添加或拖入文件后选择输出文件夹。支持 NSP/XCI 互转（可输入 NSZ/XCZ）、NSP/XCI 压缩、NSZ/XCZ 解压，以及同一游戏的本体、更新、DLC 合并为 NSP/XCI。转换独立于 Xcode、nxnative 和游戏库设置。

转换工具、Python 与依赖均随璃游内置，无需另装 SAK-Mac，也无需首次运行下载。命令调度和进度解析参考 [SAK-Mac](https://github.com/ggaoph-lab/SAK-Mac) 的 `c8e0baa59a168d9efaa0b556af70e0a08bda51de`，来源与许可详见[第三方许可](第三方许可.md)。

已有有效游戏库密钥时可直接复用。“导入转换密钥…”会单独保存自己的 `prod.keys`，不覆盖游戏库密钥；页面会显示正在使用哪套密钥。

输入会先复制并校验，再于私有临时目录处理。任务显示进度、日志，支持取消及重试；失败或取消保留原文件和已有输出。成功产物通过容器结构和复制哈希检查后，原子导出到新的独立文件夹，不覆盖旧结果；这些检查不代表游戏签名或可玩性验证。完成任务提供“查看转换结果”和“导入生成的 NSP”，后者仍需通过游戏库原有的环境与元数据检查。

## Xcode 与 Metal 组件

“在 App Store 获取 Xcode”直接打开 Mac App Store 中的 Xcode 页面，设置和首次运行向导使用同一入口。设置页和项目首页不展示兼容性配置列表，历史测试范围见[验收记录](验收记录.md)。

“安装 Metal 编译组件”使用 Apple 的 `xcodebuild -downloadComponent MetalToolchain`；已安装时禁用安装按钮。当前 Xcode 支持命令行卸载且检测到 Metal 时，提供“卸载 Metal 编译组件…”，确认后使用 `xcodebuild -deleteComponent MetalToolchain`。这是共享组件，卸载会影响其他依赖该编译器的项目；游戏、密钥与存档保留，再次准备游戏前需要重新安装。

游戏运行、准备队列或组件管理任务进行中时，安装与卸载禁用。操作成功、失败或取消后都会重新检查实际状态。当前 Xcode 不支持卸载接口时，卸载按钮禁用。应用通过 Apple 工具管理组件，不手动删除 Xcode 或组件目录。

## 键鼠和手柄

游戏详情可编辑每游戏配置；设置页可以编辑全局默认。保存后在下次启动生效，不需要重新编译。重复输入会提示冲突并禁止保存。按键录入支持 Shift、Ctrl、Option 以及组合键；Command 留给系统，Esc 留给鼠标捕获。

以下映射需要所选引擎实现 `DM_INPUT_CONFIG`。不支持时编辑器会提示，游戏使用引擎自己的默认操作；仅保存映射不会修改引擎。

《旷野之息》默认：WASD 移动，鼠标转视角；E=A，Shift=B，空格=X，左键=Y，右键=ZL；Q=L，G=R，R=ZR；Ctrl=左摇杆按下，C=右摇杆按下；Tab=＋，M=－；方向键=十字键。Esc 切换捕获；没有旧版重复别名。其他游戏显示 Switch 按钮名称。

“鼠标与摇杆”可调整横纵灵敏度、反转、停止回中、摇杆死区与轴映射。触屏模式下左键用于触屏指针，优先于左键按钮绑定。失焦、最小化和系统文字输入框出现时释放捕获并清空输入。需要触屏指针的游戏应选择触屏模式。

手柄通过 macOS GameController 接入，支持一个扩展手柄。默认按物理位置：east=右侧 A，south=下方 B，north=上方 X，west=左侧 Y。支持双摇杆、扳机、肩键及方向键；不含体感和震动。手柄断开后其输入立即清空。“输入测试”可查看实际设备状态。

## 生成 IPA

在游戏详情中点击 **生成 IPA…**，选择游戏库以外的保存位置，即可从已导入的本体、更新和 DLC 生成 **iPhone / iPad 未签名游戏包**，无需先准备 Mac 运行版本。额外需要在所选 Xcode 中安装 iOS 平台和 Metal 编译组件，并运行 `brew install xcodegen` 安装 XcodeGen；缺少时会提示修复。

请先等待游戏退出及准备队列结束。“准备任务”中显示导出进度，可取消、重试，完成后在访达中显示文件，任务卡片也可再次打开。失败或取消保留上次成功的 IPA、Mac 运行版本和存档。安装前需用自己的安装工具签名；iOS 的设备要求和游戏兼容性取决于所选引擎，Mac 的游玩记录不代表 iPhone / iPad 验收。

## 构建报错与着色器警告

耗时操作共用进度条，覆盖任务页、全局任务提示、向导和设置。导入、复制/副本/缓存校验、引擎准备、游戏/着色器构建、IPA 导出、环境/组件操作、清理及诊断均提供进度；总量已知时显示真实计数及百分比，未知或估计总量使用线形不定进度条和已用时间。普通日志、警告和心跳不清空已有计数；其他页面可点击“查看全部任务”继续跟踪。

错误提示包含建议处理方式和错误代码。“查看失败任务”可查看失败阶段及脱敏编译器输出，“打开对应日志”直接定位该任务的日志文件，包括构建缓存内的着色器日志；“复制错误摘要”方便反馈。原始日志仍保留在本地，分享前请检查。

Metal/SDK 缺失、着色器转换或编译失败、着色器链不匹配、空间/权限问题和可能的内存不足分别提示。没有可用着色器时停止构建；部分失败会标记“完成（有警告）”，复用缓存仍显示警告。按建议修复后重试，不能把“准备完成”视为所有场景画面正常的保证。

## 任务、文件和恢复

- 同时只准备一款游戏，准备与游戏运行互斥。准备时可以继续导入和修改设置。
- 取消会停止相关子进程；重试重新验证已完成阶段，未完成阶段重新执行。工具链变化会创建新的缓存。
- 安装时原子切换成功运行目录；失败不会覆盖上一个成功版本。存档和运行时图形管线记录独立保存。首次进入新场景仍可能卡顿。
- 应用重启后保留游戏库和任务。中断任务需要手动重试。
- “移出游戏库”只隐藏条目，保留托管文件和存档；再次导入可恢复登记。“清理缓存”和“删除托管 NSP 副本”分别确认，均不删除玩家原始文件和存档。
- 存档在 `<游戏库>/saves/<Title ID>`；运行目录在 `games/<Title ID>/current`；源文件在 `sources`；构建缓存在 `cache`；运行时管线记录在 `games/<Title ID>/pso_user`。可在游戏详情打开存档位置。
- 现有《旷野之息》玩家可先导入 NSP，再在详情中选择“迁移已有旷野之息构建”，选择原 `BreathOfTheWild` 文件夹。仅接受版本和着色器链一致、资源完整的来源，会重新构建主程序。旧目录和旧存档不受影响。
- 设置中的“导出诊断包”仅导出状态及经过清理的文本日志，不包含密钥、游戏、存档或着色器缓存。

## 当前边界

支持 NSP、XCI 文件与文件夹、本体/更新/DLC，接入固定 nxnative 配置。NSZ、XCZ 添加后自动解压并导入；模拟器后端、联网、体感及震动不在当前范围。具体实测结果和硬件限制见随源码的验收记录。实验性游戏可能无法启动或完成游戏；不会根据文件名猜测适配版本。


## 外观与升级

璃游采用系统原生 Liquid Glass，跟随 macOS 明暗外观及“减少透明度”，在 macOS 27 检查；最低支持目标仍为 macOS 26。更名保留旧版 NS Mac 的应用标识、游戏库与映射。不要同时运行新旧版本。图标的 ICO 用于通用分发，Mac 应用使用 ICNS。上游来源、风险和版权说明见 README 及第三方许可。

## 界面语言

应用默认跟随 macOS 语言；首次运行向导和“设置 → 语言”均可切换 English、简体中文或跟随系统，界面立即更新并记住选择。切换无需重新导入游戏、密钥或重新编译。向导、映射、任务进度、已有任务记录和应用错误提示均支持两种语言；游戏内容和原始编译日志保持原样。系统文件对话框的内置按钮跟随 macOS 语言。

## 游戏语言

在游戏详情、启动按钮旁选择“启动语言”。“跟随默认”使用“设置 → 游戏语言 → 默认游戏语言”的选择，初始默认为简体中文；单独设置的游戏优先使用自己的选择，重启璃游后保留。游戏语言与启动器界面语言相互独立。

退出游戏并重新启动后生效，无需重新准备或导入固件。璃游通过 `DM_LANG` 向 nxnative 传递标准 Switch 语言代码。语言设置不会增加游戏本身没有的翻译；导入版本和引擎必须支持所选语言，部分游戏还会使用自己的已保存语言设置。如果已准备游戏仍忽略其支持的语言，请反馈游戏版本、语言选项及脱敏后的运行日志。

## 应用外观

在“设置 → 语言与外观 → 外观”选择“跟随系统、浅色或深色”。选择立即生效，重启后保留；只控制璃游，不修改 macOS 的全局外观。
