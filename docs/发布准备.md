# 璃游 LumaDock 发布流程

当前版本：0.2.7。项目面向 Apple Silicon Mac。默认英文 README，保留中文版、上游致谢、版权与风险说明；首页不展示支持游戏列表，历史测试范围保留在验收记录中。

仓库：[Xc1Ym/LumaDock](https://github.com/Xc1Ym/LumaDock)。安装包入口：[GitHub Releases](https://github.com/Xc1Ym/LumaDock/releases)。

## 公开源码与数据边界

公开内容使用发行源码清单：`Sources`、`Worker`、`Assets`、`scripts`、`tests`、`docs`、`.github`、`Package.swift`、`product.json`、`requirements-runtime.txt`、两份 README、LICENSE 和 .gitignore。保留通用运行库许可证及外部引擎接口说明。应用、DMG、源码 ZIP 均不得包含 nxnative 源码、读取器或翻译器二进制；CI 不下载 nxnative，用原创接口夹具测试。

不上传 `work/`、`release/`、`.build/`、`Runtime` 链接及其目标、游戏、固件、密钥、存档、游戏封面、玩家缓存、私人日志、请求或诊断。Git 提交和源码包应逐项核对清单；不使用包含私人文件的整个工作区上传。

## CI 与发布

工作流为 `.github/workflows/ci.yml`，GitHub 官方 Actions 固定到已核对的提交。普通分支、PR、手动运行只生成构建附件；`v*` 标签增加发布任务。

1. 同步 `product.json` 中的版本与构建号，以及 README 和发行说明。保留应用标识及玩家数据目录。
2. main/master 的 CI 在 macOS 26 ARM64 runner 完成 Python / Swift 回归测试、macOS/iOS 实际 Metal 编译与失败诊断验证、原创 UIKit 样例的未签名 IPA 校验、图标生成、可搬移依赖收集、应用编译、本地签名、DMG 与源码包生成和校验。Metal 样例需要 Apple Metal Toolchain，iOS 样例需要 XcodeGen；均不使用玩家游戏或引擎。
3. 发布前完成本地测试和发行包校验。需要确认远端结果时，检查 CI 和构建附件；只凭本地测试或 workflow YAML 不能声称远程成功。若发布者明确要求不监控 CI，可以推送标签后交由标签流水线完成验证和发布，并明确远端结果尚未确认。
4. 创建与 `product.json` 一致的版本标签，例如 `v0.2.7`。标签流水线重复完整验证，包括运行库加载路径审计与应用改名、中文及空格目录搬移后的实际工具启动；不匹配的标签会被拒绝。
5. 只有 Mac 作业成功后，发布作业才下载该次作业的明确公开附件，复核 SHA256SUMS，从源码包读取发行说明，创建或续传草稿 Release。全部附件上传后才公开 Release。

版本标签的发布权限仅授予发布作业，普通构建使用 `contents: read`。发布失败可以重试草稿；已公开版本不直接覆盖，应更新版本号。CI 不使用 Apple ID、Developer ID 或公证密钥，不运行玩家游戏。

发布附件为 ARM64 DMG、源码 ZIP、SHA256SUMS、发行审计及 ICNS / ICO。CI 使用 Apple 与 Homebrew 当时提供的构建工具；具体运行环境记录于应用内 Runtime/versions.json，不保证逐字节重建一致。

## 本地与发布后验证

按[开发说明](开发说明.md)执行构建和 `scripts/verify_release.py`，校验图标、源包清单、数据边界、签名、DMG 和 SHA-256。发布后还需核对 Actions 运行、Release 附件大小和下载校验和，确认 DMG 来自成功的远程构建。

当前安装包采用 ad-hoc 签名，尚未 Developer ID 签名或公证。正式签名、公证及票据装订需另行配置受保护的发布环境。不要在仓库中加入证书、密码、Nintendo 标志或游戏截图作为品牌素材。
