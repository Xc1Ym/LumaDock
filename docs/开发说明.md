# 璃游开发说明

[English](Development.md) · [项目首页](../README.zh-CN.md)

启动器使用 SwiftUI / AppKit 与 Python Worker，nxnative 内置于 `Engine/nxnative`。CI 同时运行原创接口夹具、原生引擎测试与编译检查，不需要游戏或密钥。具体边界见[架构说明](架构说明.md)与[引擎接口](引擎修改.md)。

## 测试与本地构建

需要 Apple Silicon Mac、完整 Xcode、Homebrew，以及 `PATH` 中可用的 [.NET 10 SDK（macOS Arm64）](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)。在仓库根目录执行，按实际位置调整 `DEVELOPER_DIR`。

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
mkdir -p work
brew install python@3.14 spirv-cross zstd xcodegen actionlint
"$(brew --prefix python@3.14)/bin/python3.14" -m venv work/python-venv
work/python-venv/bin/python -m pip install -r requirements-runtime.txt -r requirements-build.txt
actionlint .github/workflows/*.yml
work/python-venv/bin/python -B -m unittest discover -s tests -v
swift test --disable-sandbox --cache-path "$PWD/work/spm-cache" -c release
```

实际 macOS / iOS Metal 编译与合成 UIKit IPA 检查还需在 Xcode 中安装 iOS 平台，然后执行：

```bash
xcodebuild -downloadComponent MetalToolchain
work/python-venv/bin/python -B scripts/check_shader_diagnostics.py
```

生成应用、DMG 与源码包，并校验签名、运行库搬移及校验和：

```bash
swift scripts/make_icons.swift
work/python-venv/bin/python -B scripts/bundle_converter.py
work/python-venv/bin/python -B scripts/bundle_runtime.py
work/python-venv/bin/python -B scripts/bundle_engine.py
work/python-venv/bin/python -B scripts/package.py
work/python-venv/bin/python -B scripts/source_archive.py
work/python-venv/bin/python -B scripts/verify_release.py
```

打包器拒绝覆盖仍在运行或仍有运行时子进程使用的目标应用。测试期间可用 `scripts/package.py --output-dir release/local-preview --app-only` 输出到独立目录。完整应用先在暂存目录签名与验证，再发布到目标路径；发布或搬移后的运行时验证失败时恢复旧包。

产物位于 `release/`。依赖的实际版本记录在应用内 `Runtime/versions.json`；工具链随构建环境变化，不保证逐字节可复现。

DMG 使用 LZMA（`ULMO`）压缩。运行环境暂存时清除 Python 开发示例、fontTools 生成的 C 文件及 Crypto 自测代码，并在签名前仅保留通用二进制的 ARM64 架构。运行模块、引擎配置、许可及依赖对应源码压缩包均保留，支持离线使用。打包时也会对已有运行环境副本执行相同优化，不修改 `work/Runtime` 或正在运行的应用。

开发使用忽略的 `work/` 目录。通过 `--data-root <目录>` 启动可隔离应用数据。不要提交 `work/`、`release/`、`Runtime`、游戏、密钥、存档或玩家缓存。

转换收集脚本 `scripts/bundle_converter.py` 固定 SAK-Mac、NSC_BUILDER、nsz 提交及 `requirements-conversion.txt` 中的 Python 依赖版本。发行构建时联网收集、应用上游 macOS 补丁，保留许可及 GPL/MPL 依赖对应源码，排除密钥、标题数据库和玩家内容。应用离线调用内置工具。准确上游提交、依赖版本、源码地址及哈希写入 `Runtime/converter/manifest.json`。

## CI 与发布

[GitHub CI](../.github/workflows/ci.yml) 在 macOS ARM64 runner 上测试、构建和校验。main/master push、PR 与手动运行生成构建附件，保留 14 天；匹配 `product.json` 的版本标签只在 Mac 构建和校验和检查通过后发布 Release。Release 仅附带 CI 生成的 DMG，SHA-256 写入发行说明；源码 ZIP、校验清单、审计及图标保留为 CI 内部产物。

当前安装包采用 ad-hoc 签名，尚未公证。CI 不运行商业游戏，也不代替真机验收。详见[发布流程](发布准备.md)与[验收记录](验收记录.md)。

每日同步时间为北京时间 03:00（GitHub 调度可能延迟）。`scripts/sync_engine.py` 记录上游提交和文件哈希，排除截图及私有文件，重新应用 Mac/iOS 共用手柄规则；接口变化时同步失败。候选版本通过完整复用 CI（含打包和搬移验证）后才普通推送 main；main 已变化时拒绝过期候选，测试失败保留旧引擎。不创建标签或 Release。需要最新同步版本时按上文自行编译 App/DMG，Release 仅按需提供。分支保护若禁止机器人写入，需要管理员配置；流程不强推或绕过保护。
