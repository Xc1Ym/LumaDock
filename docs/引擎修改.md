# 外部引擎接口与私有适配

璃游不再分发或固定内置 nxnative 源码，不提供下载按钮，也不自动下载引擎。玩家在向导或设置中指定自行获取的源码根目录；应用不改动原目录。

`Worker/engine.py` 验证根目录包含 `dm`、`scripts`，以及 Mac 宿主、NSP 读取器、翻译器源码/二进制和游戏配置。构建脚本必须提供 `Progress`、`extract`、`extract_aoc`、`rewrite`、`split_shaders`、`build_mac_host`；需要运行时采集的配置还依赖对应采集函数。未来上游接口变化可能需要适配，不以猜测或跳过校验放行。

“准备引擎工具”使用用户安装的 .NET 10 SDK，将读取器编译到应用私有目录。NuGet 依赖独立保存。读取器及翻译器都不进入应用、DMG 或源码 ZIP。

适配只作用于私有副本：

- `Worker/NspMetadata.cs` 是璃游自己的元数据协议扩展，依赖所选外部读取器已有的 LibHac 辅助函数。若读取器尚无 `--inspect`，在副本中通过 partial class 接入，提供 CNMT 类型/版本、NACP 名称/封面及 NSO build ID；不复制整个上游读取器到发行包。
- 对仍查询其他 SDK 的旧工具链脚本，仅在私有副本中将 Metal 检查限定为 macOS。随后按实际工具更新锁、生成 chain header 并检查指纹，不跳过一致性校验。
- 不自动注入旧版 Mac 前端/输入补丁。只有引擎已实现 `DM_INPUT_CONFIG` 才能使用璃游映射；否则明确提示并使用引擎自身操作。

缓存身份包含选中源码内容及璃游适配版本，不只依赖目录名、mtime 或 Git HEAD。源码目录移动而内容不变可复用工具，修改则隔离新缓存。生成目录、游戏与密钥不作为引擎源码输入。指向目录外的符号链接拒绝使用。工具缓存记录产物哈希与适配后源码指纹，残缺或损坏不算成功。

历史内置引擎版本和游戏验收记录仅保留在验收文档中，不代表任意新选外部引擎已实测。

启动时通过 `DM_LANG` 传入 `nn::settings::LanguageCode` 标准代码（例如简体中文 `zh-Hans`、繁体中文 `zh-Hant`、英语 `en-US`、日语 `ja`），由引擎的 `GetDesiredLanguage` 接口读取。全局默认与每游戏覆盖保存在启动器偏好中，不进入构建缓存身份；未指定时默认 `zh-Hans`。Worker 拒绝非白名单代码，避免将界面语言标识或错误的 `zhHans` 继续交给游戏。此设置不修改固件、资源或存档，也不保证任意外部引擎及游戏均实现所有语言。
