# 架构与接口

SwiftUI 提供游戏库、任务页、设置和首次运行向导。AppKit 提供多文件/目录选择、拖放及键盘事件录入；GameController 提供设备测试。所有游戏转换由独立 Python Worker 运行，游戏宿主再作为独立进程启动，异常不会结束启动器。

## 私有存储

应用私有根目录：`~/Library/Application Support/NSMac`。密钥位于 `keys/prod.keys`（0600），目录权限 0700。`preferences.json` 记录所选游戏库、外部 nxnative 目录和 Xcode 路径；`engines` 保存按源码指纹隔离的私有引擎副本和读取工具；`jobs` 持久化任务，`requests` 保存临时 0600 请求文件，`logs` 保存运行文本日志。诊断只读取作业状态和允许的日志文本，不包含请求、密钥、源文件、缓存或存档。

外置盘使用 `.nsmac-library.json` 的 UUID 验证连接，缺失或 UUID 不一致即停止，不在同路径偷偷创建替代库。游戏库 `catalog.json` 以临时文件、fsync、rename 更新，并使用 advisory flock 防止同库并发提交。

源文件默认 APFS clone，失败后复制，再进行完整 SHA-256 复核。CNMT 来自经 LibHac 完整性验证解密的 Meta NCA，类型和版本由 CNMT 决定；Control NCA 提供 NACP 名称/显示版本及封面，Code NCA 提供 NSO build ID。文件名不参与分类。

## 导入顺序与准备队列

首次运行按“检查并安装环境（指定外部 nxnative 并准备工具） → 选择游戏库 → 导入 prod.keys → 添加游戏”引导。环境检查通过后才能继续；缺少 Apple 工具时显示安装入口和步骤。游戏添加按钮、菜单与拖放共用前置检查，环境未就绪时定位到第一步，缺少密钥时定位到第三步。环境检查和 Metal 安装不依赖旧游戏库磁盘在线。密钥导入先检查格式，NSP 读取再验证解密能力；catalog 的 keys.ready 会读取实际密钥文件并验证格式，不仅依赖历史 status.json，密钥丢失或损坏时重新引导导入。

prepareAfterImport 默认为开启，可在向导或设置关闭并持久化；旧版 preferences 缺少该字段时仍可读取。成功导入后仅处理本轮新增内容涉及的游戏，刷新元数据后检查完整性、适配状态、已有运行产物和工具链。满足条件才加入串行准备队列，重复导入不排队，未满足条件保留导入结果。不会自动启动游戏。异步结果核对游戏库 UUID，避免切换库后提交到错误的队列。

游戏语言与界面语言分别保存。`preferences.gameLanguage` 是全局默认，`gameLanguages` 按 Title ID 保存每游戏覆盖；缺少或未知值回退到有效默认，初始为 `zh-Hans`。设置在下次启动时读取，不进入构建身份，也不触发准备任务。

## 独立文件转换

`convertFiles` 使用随应用分发的 `Runtime/converter`（SAK-Mac 调度、带 macOS 补丁的 NSC_BUILDER、nsz 和独立依赖目录）与内置 Python，不依赖游戏库或 nxnative。`converterStatus` 检查组件及密钥；`conversionKeys` 将自己的转换密钥单独原子写入 `converter/keys/prod.keys`（0600），优先于游戏库密钥。发行构建联网收集固定版本，应用运行时不下载后端。

输入先在私有 `converter/work/job-*` 中复制并校验，再交给子进程。NSC_BUILDER 的代码、配置和密钥同样使用每任务临时副本，应用资源只读；NSZ 通过参数读取密钥。后端进度解析机器可读 JSON 与 tqdm 百分比；退出成功但日志报错、无产物或容器表异常均拒绝导出。结果在目标磁盘暂存并复核 SHA-256，最后原子重命名为唯一目录，不覆盖已有输出。取消清理临时副本，任务保存转换参数供重试。生成 NSP 的入库仍经过原有环境和元数据检查。转换任务独占 `.toolchain.lock`，避免同时构建、运行或修改组件。

## Worker v1

调用方式为参数数组：`[python, main.py, --request, privateRequestPath]`。不会将玩家路径拼接到 shell。请求至少包含：

```json
{"schema":1,"taskId":"UUID","operation":"build","privateRoot":"/private/app-data","resources":"/app/Contents/Resources","engineDir":"/volume/nxnative","library":"/volume/library","libraryId":"UUID","gameId":"01007EF00011E000","developerDir":"/Applications/Xcode.app/Contents/Developer"}
```

`launch` 请求额外携带已解析的 `gameLanguage`（例如 `zh-Hans`）；Worker 校验 18 个标准 Switch 语言代码并设置游戏子进程的 `DM_LANG`。旧请求未指定时默认 `zh-Hans`，非法代码在启动子进程前拒绝。不会借用父进程或界面语言的值。

stdout 每行一个 JSON 对象，stderr 不混入协议。示例：

```json
{"schema":1,"taskId":"UUID","type":"progress","stage":"转换并编译 Metal 着色器","stageIndex":6,"stageCount":8,"done":4059,"total":19592,"unit":"shaders","elapsed":131.7,"message":"compiling"}
```

事件包括 `stage`、`progress`、`heartbeat`、`cache`、`stageComplete`、`message`、`diagnostic`、`result`。可靠文件/字节/着色器计数才提供 total，估计总量不作为确定百分比。未知阶段使用线形不定进度条，每秒 heartbeat 覆盖包括纯 Python 操作在内的任务。`resetProgress` 清空子阶段旧计数，普通消息、警告和心跳不清空进度。普通任务不根据未知总量显示百分比。游戏准备和 IPA 另以里程碑的本机历史及当前实测速率给出参考 ETA，不跨不同步骤直接混合计数。

所有耗时任务共用 `TaskProgressView`，任务页显示阶段完成度及当前计数；其他页面显示全局任务提示，设置/向导在环境检查、引擎和组件操作位置显示进度。文件复制、校验、阶段缓存、引擎复制、清理、诊断导出均报告实际工作量。`exportIPA` 使用独立 iOS 身份缓存，复用上游构建和打包进度；上游估计的编译/归档总量仅作不定进度计数。

诊断保留 `code`、`severity`、`summary`、`suggestion`、`stage`、`component`、`exitCode`、脱敏 `detail` 及本地 `logPath`。任务文件和结果事件均携带诊断，复制摘要不含日志绝对路径。进程返回成功但着色器成功数不足时生成警告；零成功停止构建。阶段检查点同时持久化警告，缓存复用会重放警告。Swift 原生启动失败和异常退出也保存为可查看的诊断。

状态：queued → running → completed / failed / cancelling → cancelled。启动器退出或崩溃后正在运行/排队的任务恢复为 interrupted，由用户重试。Worker 检测启动器父进程消失并取消子进程。每个子进程有独立进程组，取消先 SIGTERM，3 秒后 SIGKILL。构建和游戏运行共享库级 execution 锁；导入不占此锁。

## 构建、缓存与安装

直接调用玩家选择的外部引擎的提取、代码重写、运行时捕获、着色器转换与 Mac host 编译函数，生成 macOS 运行产物，仅使用已适配的游戏配置。引擎原目录与应用资源保持只读。读取器由用户安装的 .NET 10 SDK 在私有副本编译；构建目录也使用单独的可写引擎副本。没有内置或自动下载引擎。实际编译器/工具指纹更新私有工具锁，生成对应 chain header、着色器、c1 表和主程序，不跳过检查。

缓存身份覆盖引擎源码、源 NSP 完整指纹、工具链、游戏配置。阶段完成记录每个产物的大小及 SHA-256。重试校验成功后复用；损坏或半成品重新执行。输入配置独立保存，不参与构建身份。外部源码或璃游适配代码变化会生成新身份，不跨不同引擎复用未验证阶段。已有成功运行版本保留；不对任意外部版本自动沿用历史兼容结论。

NVN：shader split 结果必须与固定 profile 数据行一致；Metal 库和 reflection 必须属于当前链；c1_guard 使用未改变的上游证明规则，可并行执行。Vulkan：SPIR-V 经 SPIRV-Cross 转换，生成 Mac Metal 库和资源表；有运行时捕获要求的游戏先完成捕获。采集使用隔离存档目录。

成功产物先写 `games/<id>/install.partial`，完整性验证后放入唯一 releases 子目录，通过临时 symlink rename 原子切换 `current`。旧 release 保留。存档、临时目录、运行时管线记录和映射分别位于 saves/temp/games/<id>/pso_user/mappings。

## 工具链管理

`installMetal` 和 `uninstallMetal` 通过独立 Worker 调用 `xcodebuild` 的 MetalToolchain 组件接口。卸载请求必须携带 `confirmed: true`，并在执行前探测当前 Xcode 的 `-deleteComponent` 支持；不使用路径删除作为回退。preflight 返回可选的 `canUninstallMetal` 能力字段。

组件管理独占应用私有目录下的 `.toolchain.lock`；构建、迁移和游戏运行持有共享锁，跨同一私有目录的 Worker 实例也会互斥。界面同时阻止执行任务或排队期间修改组件。完成后重新检查工具链，环境不就绪时不启动后续准备任务。此锁不协调外部 Xcode 项目或采用不同私有目录的其他程序，因此卸载确认明确提示共享组件影响。

## DM_INPUT_CONFIG v1

此接口为可选能力。所选引擎未实现时，界面提示使用引擎自身操作，保存映射不会注入前端补丁；对应运行产物不会接收无效的配置承诺。

启动前写入私有 JSON 配置，宿主从 `DM_INPUT_CONFIG` 读取。配置包含 `schema`、`keyboard`、`mouse`、`gamepad`、`axes`、`mouseOptions`、`deadzone`。目标使用 Switch 名称和 `LS_UP` 等方向名。键盘是 macOS 虚拟键码和修饰键位掩码（Shift=1、Ctrl=2、Option=4），鼠标是 0–4，手柄按 east/south/north/west 等物理位置。

每种设备内物理绑定唯一；冲突拒绝保存。组合键优先于同键的无修饰绑定，组合中消耗的独立修饰键不会同时发送另一个目标。Esc 保留给捕获，Command 快捷键交还系统。鼠标/键盘输入与手柄输入分别发布到引擎；失焦/最小化/系统文字输入时清空，重新聚焦后重新采样手柄，断开立刻归零。

## 游戏处理里程碑

`Worker/milestones.py` 与 `MilestoneProgressView.swift` 参考 S2Arm 的阶段计划、预计秒数中位数和校准算法。按实际路径列出各次解包、DLC、代码重写、可选捕获、着色器提取/编译及 Mac 安装或 iOS 打包/校验/导出；不插入 nxnative 未执行的 S2Arm 管线预建等步骤。普通任务继续使用原进度条。

Worker `plan` 事件提供 `milestones`（id、label、purpose、expected、source、samples），后续事件携带当前 `milestone` 与 `milestoneCached`；阶段事件附 `milestoneStarted` 的墙钟起点，后端实测耗时采用单调时钟。任务记录保存这些字段，旧任务字段可缺省。`begin` 的阶段索引固定在当前里程碑，内部日志切换不递增总阶段。

成功任务的非缓存阶段写入私有 `stats/prepare-<身份>.json`，最多 50 条。身份覆盖游戏、Mac/iOS 目标和完整工具链指纹；有历史时按适用阶段的游戏体积换算取中位数，否则明确显示初始参考估时。当前真实进度超过 5% 且有足够耗时时按本步速度外推，后续步按已完成非缓存步骤实际/预计的比例校准（0.5–3 倍）。未知总量只用浅色估计填充，不产生数字百分比；窄窗口先分配最小宽度再归一化。损坏或无法写入的统计文件不会阻断游戏准备，失败/取消不记成功历史。历史不进入构建身份或缓存检查点。
