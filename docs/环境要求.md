# 运行与构建环境

首次设置第一步与“设置 → 运行与构建环境”共用同一套实时检查。每项均可展开“安装与修复方法”。检查在本机执行，使用一次性的原创测试程序，不读取游戏或密钥，不自动安装软件或接受 Apple 许可。

每次启动应用时自动检查一次。打开设置或重新打开首次运行向导会复用本次结果，包括未通过的检查。需要时可点击“重新检查”；切换 Xcode、游戏库或安装、卸载组件后也会重新验证。

| 环境 | 来源或安装方法 | 验证内容 | 使用阶段 |
| --- | --- | --- | --- |
| Apple Silicon、macOS 26+ | 使用 Apple Silicon Mac，在“系统设置 → 通用 → 软件更新”升级系统 | 原生 arm64 进程、系统版本，不支持通过 Rosetta 运行 | 准备与启动 |
| 系统 Metal 图形设备 | 随 macOS 提供，在本机桌面会话中使用 | 系统实际能够创建 Metal 设备 | 准备与启动 |
| 完整 Xcode | 点击“在 App Store 获取 Xcode”安装，打开一次，手动完成许可和初始组件安装 | 实际所选 Xcode 包含 Mac 平台，能报告版本并通过首次设置状态检查 | 准备 |
| macOS SDK、clang、make、ar、codesign | 随完整 Xcode 提供；非默认位置使用“选择 Xcode.app…” | SDK 26+、实际编译链接 arm64 程序及宿主需要的系统框架、测试程序本地签名、make 与静态库生成 | 准备 |
| Metal 编译组件与 metallib | 完成 Xcode 设置后点击“安装 Metal 编译组件” | 实际编译原创测试着色器并生成 macOS Metal 库，不只检查文件路径 | 准备 |
| 内置 Python 3.14 | 已包含在完整应用中，不需要另外安装 | 隔离启动、版本清单一致、原生 arm64、所需标准库可用、使用内置目录 | 准备与启动 |
| capstone、lz4、fontTools | 内置 Python 扩展 | 实际导入、版本匹配、arm64 反汇编样例、LZ4 压缩解压、字体库加载 | 准备 |
| .NET 10 运行时 | 应用自带，玩家不需要 .NET SDK | 从内置目录加载所需版本的运行时 | 准备 |
| NSP 读取器与 LibHac | 应用自带 | 不读取玩家内容，启动程序并检查使用说明输出 | 导入与准备 |
| 着色器翻译器 | 随固定引擎提供 | 能启动，嵌入的源码指纹与固定引擎一致，所需 DLL 齐全 | 准备 |
| SPIRV-Cross、Zstandard | 应用自带 | 实际启动并报告身份信息 | 准备 |
| 游戏库存储 | 选择可读写的本地或外置磁盘，并保持连接 | 游戏库身份、临时文件读写、卷上允许执行程序、可用空间 | 准备与启动 |

通用检查至少要求 5 GB 可用空间；准备前还会根据所选游戏源文件大小重新检查。大型游戏通常需要 40–80 GB 或更多，通用门槛不代表足够构建任意游戏。

## 安装 Apple 环境

1. 从按钮进入 App Store 安装完整 Xcode。单独安装 Command Line Tools 不属于璃游支持的完整环境。
2. 点击“打开 Xcode 完成设置”，由玩家在 Xcode 中完成 Apple 许可和首次组件安装。
3. 若 Xcode 不在默认位置，点击“选择 Xcode.app…”，随后“重新检查”。璃游只为自己的子进程设置 `DEVELOPER_DIR`，不修改全局 `xcode-select`。
4. 缺少 Metal 时点击安装，应用采用 Apple 的 `xcodebuild -downloadComponent MetalToolchain`，结束后重新验证实际编译。参考 [Apple 官方组件安装说明](https://developer.apple.com/documentation/xcode/downloading-and-installing-additional-xcode-components)。
5. 每项失败都会提供对应修复方法和可用操作。可展开查看工具原始错误。找不到工具、工具无法启动或超时，均作为失败状态显示。

本流程只使用 macOS SDK 和编译器。玩家无需安装模拟器运行环境、`xcodegen`、独立 Vulkan SDK、Homebrew、系统 Python 或 .NET SDK。Apple 框架、libvpx、libdeflate 与 Vulkan 头文件由系统、Xcode 或内置引擎源码提供。

### Xcode 初始设置仍未通过

展开“Xcode 初始设置”的“安装与修复方法”，可查看实际选择的 Developer 目录、状态检查命令和错误输出。命令无输出但失败时也会显示退出码。首次启动任务未完成、命令报告的许可错误和超时分别提示。

先打开所选 Xcode，完成许可及必需组件设置，再回到璃游。若已完成设置，可先点击“重新检查”或退出后重新打开璃游。仍未通过时查看具体诊断；确需手动初始化时，先阅读并同意 Xcode 许可，再点击“复制修复命令”，自行在终端执行。Apple 的 `-runFirstLaunch` 会安装系统组件并接受许可，璃游不会自动执行该管理员命令。命令使用所选 Xcode 路径，不修改全局 `xcode-select`。参考 [Apple 组件安装说明](https://developer.apple.com/documentation/xcode/downloading-and-installing-additional-xcode-components)。

## 修复应用内置组件

不要用 `pip` 修改应用内置 Python，也不要从其他应用复制零散可执行文件。请从[璃游官方 Release](https://github.com/Xc1Ym/LumaDock/releases/latest)重新下载完整 DMG，将整个应用复制到“应用程序”，重新打开并检查。保留现有游戏库和私有玩家数据。正式应用不会悄悄改用 Homebrew Python；即使 Python 缺失导致 Worker 无法启动，原生启动器也能显示对应失败项目和重装入口。

已准备好的游戏，在运行文件完整、所有“启动”项目通过时，不要求保留 Xcode、Metal 编译组件、.NET 或仅构建所需的 Python 扩展。Python 仍用于监督游戏进程。再次准备、更新或重建游戏时需要恢复完整构建环境。源码开发和发行包制作另有维护者依赖，见 README。

## 组件路径和离线说明

内置组件相对于当前应用包定位：`LumaDock.app/Contents/Resources/Runtime/`。运行时，启动器根据应用当前的位置解析出完整绝对路径，再交给 Python 和 .NET。`.NET --list-runtimes` 输出的是这次实际加载的位置，并不是写死的开发者电脑目录。二进制依赖使用相对加载路径，打包检查会拒绝外部运行时链接及开发机搜索目录。

环境列表默认显示组件名称和版本，展开“组件位置”才显示当前完整路径。将整个应用移动到其他目录或重命名后，不需要重装 Python 或 .NET；请保持应用包完整。

“环境安装说明”会在璃游内直接打开离线阅读窗口，首次设置时也可使用，不依赖 Markdown 编辑器或 Finder。第三方许可使用同一个阅读器；“在 Finder 中显示”作为单独的可选操作保留。
