# 运行与构建环境

首次设置与设置页使用同一套检查。每次启动自动检查一次，打开设置复用结果；点击“重新检查”、切换引擎/Xcode/游戏库或组件管理结束后重新验证。环境失败时仍可“稍后设置”/Esc 返回，或“退出璃游”/⌘Q 正常退出。

## 外部 nxnative

应用、DMG 与源码包均不附带 nxnative 源码、引擎、NSP 读取器或着色器翻译器，不提供引擎下载按钮，也不会自动下载。

1. 玩家自行获取并解压完整 nxnative 源码，保留依赖和许可证。
2. 在向导或设置中点击“选择 nxnative 目录…”，选择包含 `dm` 和 `scripts` 的源码根目录。不能选择其父目录、`dm` 子目录、ZIP 或不完整副本。
3. 首次准备工具需要官方 **[Microsoft .NET 10 SDK（macOS Arm64）](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)**。选择 Arm64 的 **SDK** 安装包；只有运行时不能编译。由玩家自行完成安装，再点击“重新检查”。支持检测 Microsoft 与 Homebrew 的标准安装位置。
4. 点击“准备引擎工具”。应用将所选源码复制到私有缓存，需要时加入璃游的元数据协议适配，再编译 NSP 读取工具。首次可能从 NuGet 恢复项目的 LibHac 依赖，因此可能需要联网；此操作不下载 nxnative。
5. 完成后重新检查。已有完整工具缓存时不再要求保留 SDK；源码变化或缓存损坏时需要重新准备。

所选源码目录保持不变。源码副本、工具、NuGet 包和 SDK 工作文件位于 `~/Library/Application Support/NSMac/`，游戏构建使用游戏库中的独立目录。移动但内容完全相同的源码可复用工具；源码变化生成新身份，不会把其他引擎的产物直接当作兼容缓存。上次成功的游戏运行版本继续保留。

检查包括必需文件、构建函数、配置、翻译器源码指纹与读取器实际启动。任意 nxnative 版本不保证兼容；接口不兼容或包含目录外符号链接时会明确提示。应用不会更新源码或自动跟随分支。

输入映射需要引擎实现 `DM_INPUT_CONFIG`。未支持时使用引擎自身操作，映射编辑器明确提示，保存璃游映射不会使它自动生效。更换支持该接口的引擎后需要重新准备游戏。

## 检查项目

| 工具 | 安装或来源 | 验证 | 使用阶段 |
| --- | --- | --- | --- |
| Apple Silicon、macOS 26+、Metal 设备 | Mac 硬件与系统 | 原生 arm64、系统版本、实际创建图形设备 | 准备与启动 |
| 完整 Xcode | Mac App Store 的完整 Xcode | 从 Mac App Store 安装并自行完成许可/初始组件；选择实际 Xcode.app，仅 Command Line Tools 不够 | 准备 |
| macOS SDK、clang、make、ar、codesign | 所选 Xcode | Xcode 提供；实际编译链接原创 arm64 程序、生成静态库及本地签名 | 准备 |
| Metal 编译组件、metallib | Apple 组件管理器 | 完成 Xcode 后使用 Apple 组件安装方式；编译原创测试着色器 | 准备 |
| 外部 nxnative | 玩家提供的本地源码 | 玩家指定完整源码目录，检查接口、配置及内容指纹 | 导入与准备 |
| .NET 10 SDK | Microsoft macOS Arm64 SDK 安装包 | 玩家安装 Microsoft macOS Arm64 SDK；实际检查 SDK 清单 | 首次准备引擎读取工具 |
| NSP 读取器、LibHac | 从外部源码私有编译 | 从外部源码编译至私有缓存，不随应用提供 | 导入与准备 |
| 着色器翻译器 | 外部引擎目录 | 来自外部引擎，检查启动、源码指纹及 DLL | 准备 |
| Python、capstone、lz4、fontTools | 内置通用运行库 | 应用内置通用环境；隔离启动、版本、反汇编、压缩解压与字体库加载 | Python：准备与启动；扩展：准备 |
| .NET 10 运行时 | 内置通用运行库 | 内置通用运行时，验证版本和实际加载路径 | 读取器与翻译器运行 |
| SPIRV-Cross、Zstandard | 内置通用工具 | 内置通用工具，验证实际运行 | 准备 |

通用空间检查要求至少 5 GB；构建前按源文件大小再次检查，大型游戏可能需要 40–80 GB 或更多。

## Xcode 与 Metal

点击“在 App Store 获取 Xcode”，打开 Xcode，由玩家完成许可及首次组件安装。非默认位置通过“选择 Xcode.app…”指定，再重新检查。应用只为自己的进程设置 `DEVELOPER_DIR`，不修改全局 `xcode-select`。

Xcode 就绪后点击“安装 Metal 编译组件”，通过 Apple 的 `xcodebuild -downloadComponent MetalToolchain` 安装。支持时可确认卸载共享组件。参考 [Apple 官方说明](https://developer.apple.com/documentation/xcode/downloading-and-installing-additional-xcode-components)。这些操作不下载引擎。

初始设置仍失败时，展开“安装与修复方法”，查看实际路径、状态命令与错误。若 Xcode 已设置完成，先重新检查或退出重开璃游。可复制的手动修复命令会安装初始组件并接受许可；执行前自行阅读并同意 Xcode 许可。璃游不会自动执行管理员命令。

## 内置依赖与离线说明

通用运行环境相对应用当前位置解析，位于 `Contents/Resources/Runtime`。.NET 打印的完整路径是当前实际位置，不是开发者路径。移动或重命名整个应用不需要重装 Python/.NET，打包会审计本机二进制依赖路径。

玩家不需要系统 Python 或 Homebrew。内置组件损坏时请重新安装完整璃游，不要用 pip 修改包内 Python。引擎故障通过重新选择外部目录、重新准备私有工具缓存修复，不会回退到内置引擎。

“环境安装说明”直接打开本机内置阅读器，无需 Markdown 编辑器。已有完整运行产物且启动检查通过时，即使外部引擎暂时不可用，也可启动已准备好的游戏；导入、更新或重新准备时仍需恢复外部引擎与工具。
